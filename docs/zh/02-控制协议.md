# Despotes 控制协议

> 文档 2 / 4 | Despotes 文档集 > 版本：v26.0
> 规范语言为英文，见 [02-Control-Protocol.md](../02-Control-Protocol.md)

所有命令均为 JSON 对象。HTTP、CLI（stdin，每行一条 JSON）与 FileDrop 使用同一 schema。

## 1. 信封

```json
{
  "v": 1,
  "requestId": "可选的客户端 id",
  "type": "<命令类型>",
  ...类型专属字段
}
```

响应信封（HTTP 响应体 / CLI stdout 行）：

```json
{ "requestId": "...", "ok": true,  "result": { ... } }
{ "requestId": "...", "ok": false, "error": { "code": "...", "message": "..." } }
```

错误码：`BAD_REQUEST`、`UNKNOWN_TYPE`、`NOT_IN_GAME`、`NOT_ON_SCREEN`、`QUEUE_FULL`、`FORBIDDEN`、`TIMEOUT`、`INTERNAL`。

## 2. 动作命令（`POST /despotes/v1/actions`）

### 2.1 `key` —— 按下/释放游戏按键

```json
{ "type": "key", "keys": ["key.keyboard.w", "key.mouse.left"],
  "op": "press" | "release" | "tap",
  "holdTicks": 20, "repeat": 1, "intervalTicks": 0 }
```

- `keys` 使用 Minecraft 按键名（`key.keyboard.*`、`key.mouse.left/right/middle`）。
- `tap` = 按下后经过 `holdTicks`（默认 1）释放。
- 有画面打开时鼠标键走与 `click` 相同的点击管线，否则映射为攻击/使用。

### 2.2 `type` —— 文本输入

```json
{ "type": "type", "text": "hello", "target": "chat" | "focused" | "command",
  "submit": true, "perTickChars": 8 }
```

- `chat`：打开聊天框（如需要）、输入、可选提交。
- `focused`：追加到当前焦点编辑框。
- `command`：以 `/` 开头的聊天文本的简写。

### 2.3 `move` —— 移动状态

```json
{ "type": "move", "forward": 1, "left": 0, "back": 0, "right": 0,
  "jump": false, "sneak": false, "sprint": false, "durationTicks": 40 }
```

应用合成移动 `durationTicks`（默认 1，`0` = 持续到被另一条 `move` 取消）。

### 2.4 `look` —— 视角旋转

```json
{ "type": "look", "mode": "delta" | "absolute",
  "yaw": 90.0, "pitch": 0.0, "smoothTicks": 4 }
```

delta 模式在当前旋转上增量。pitch 钳制到 [-89.9, 89.9]。

### 2.5 `click` —— GUI 交互

```json
{ "type": "click", "x": 120.5, "y": 60, "button": 0,
  "op": "press" | "release" | "click" | "double", "shift": false }
```

坐标为 GUI 缩放坐标（与原版 GUI 同一空间）。无画面打开时 `click` 回退为世界交互（见 2.6）。

### 2.6 `use` —— 世界交互

```json
{ "type": "use", "what": "attack" | "useItem" | "placeBlock" | "drop" | "pickBlock",
  "target": { "x": 0, "y": 64, "z": 0, "face": "up" },   // place 的方块坐标
  "hand": "main" | "off" }
```

无 `target` 时，`attack`/`useItem` 作用于准星所指对象。

### 2.7 `screenshot`

```json
{ "type": "screenshot", "format": "png" | "jpg", "quality": 0.8,
  "save": false, "path": null, "maxWidth": 0 }
```

返回 `{ "width": w, "height": h, "format": "png", "base64": "..." }`；`save: true` 时返回 `{ "path": "<绝对路径>" }`。

### 2.8 `mouse` — 鼠标捕获控制

```json
{ "type": "mouse", "op": "grab" | "release" | "status" }
```

- `release`：把被捕获的鼠标光标释放回系统桌面——当游戏在你操作其他窗口时仍锁定鼠标时使用。
- `grab`：重新捕获光标用于第一人称视角控制（仅在世界内且无界面打开时生效）。
- `status`：仅报告当前状态。

返回 `{ "executed": "mouse", "op": "<op>", "captured": true|false }`。

注意：独立于本命令，Despotes 会在游戏窗口失去系统焦点时自动释放鼠标（见文档 03 的 `focus.releaseMouseOnFocusLoss`），并在重新获得焦点时恢复捕获。

## 3. 查询命令（`POST /despotes/v1/query`）

| type | result 字段 |
|---|---|
| `status` | `{ inGame, screen, player: {name, x, y, z, yaw, pitch, health, dimension}, fps, windowFocused, mouseCaptured, loader, mcVersion, despotesVersion }` |
| `screen` | `{ open, title, widgets: [{id/class, x, y, w, h, focused, label}] }`（组件树，深度限 4） |
| `inventory` | `{ hotbar, selectedSlot, slots: [{slot, item, count}] }` |
| `pending` | `{ queueSize, executing: [...] }` |

## 4. 控制端点

| 方法与路径 | 请求体 | 用途 |
|---|---|---|
| `POST /despotes/v1/actions` | 单条命令**或** `{"batch": [ ... ]}` | 执行动作 |
| `POST /despotes/v1/query` | 单条查询 | 读取状态 |
| `GET /despotes/v1/screenshot` | — | 二进制图像（`image/png`） |
| `GET /despotes/v1/status` | — | JSON 状态 |
| `POST /despotes/v1/cancel` | `{"requestId": "..."} \| {"all": true}` | 取消排队中/保持中的操作 |
| `GET /despotes/v1/oplog?limit=50` | — | 最近的可视化日志条目 |

批量按顺序执行，默认每条命令每 tick 一条；`{"batch": [...], "parallel": true}` 允许无依赖命令共享同一 tick。

## 5. CLI（stdin）

同样的 JSON，每行一条；响应为 stdout 上的单行 JSON，无前缀。会话示例：

```
{"type":"status"}
{"ok":true,"result":{"inGame":true,...}}
{"type":"key","keys":["key.keyboard.w"],"op":"tap","holdTicks":20}
{"ok":true,"result":{"executed":"key"}}
```

## 6. FileDrop 文件投放

将 `<名称>.json`（单条命令或批量）放入 `despotes-in/`。每个 tick Despotes 按文件名顺序消费至多 `fileDrop.maxPerTick` 个文件，执行后在旁边写出 `<名称>.result.json`（文件不会被删除；设置 `fileDrop.deleteAfter: true` 可删除）。
