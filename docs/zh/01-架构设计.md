# Despotes 架构设计

> 文档 1 / 4 | Despotes 文档集 > 版本：v26.0 | 状态：开发中
> 规范语言：英文（中文副本同步维护），见 [01-Architecture.md](../01-Architecture.md)

## 1. 目标

Despotes 为 Minecraft: Java Edition 提供**进程内本地控制通道**：

1. 通过**游戏自身的处理器类**注入输入（键盘、聊天、移动、GUI 点击、世界交互、视角旋转），绝不经过操作系统键鼠事件——无需窗口焦点，不与用户争夺键鼠。
2. 在**渲染线程**抓取游戏帧缓冲，窗口失焦时也可用。
3. 接受来自**可配置外部来源**的命令（游戏目录下的 `despotes.json`）。
4. **可视化**每一条外源操作：游戏内可见、落盘可查。

v26.0 非目标：服务端控制、插件脚本引擎、非回环默认开放、基岩版支持。

## 2. 分层模型

```
┌────────────────────────────────────────────────────────────┐
│ 传输层（控制源）    HTTP / CLI(stdin) / FileDrop 文件投放    │
│                    + 插件 SPI（v26.1+）                     │
├────────────────────────────────────────────────────────────┤
│ 协议层             JSON 命令 schema（actions/query/shot）   │
├────────────────────────────────────────────────────────────┤
│ 调度器             队列 → 游戏线程排空（每 tick 1 条）        │
│                    安全闸门 · 来源标记                        │
├────────────────────────────────────────────────────────────┤
│ 动作层             Key · Type · Move · Click · Look ·       │
│                    UseItem · Screenshot · Query · Config    │
├────────────────────────────────────────────────────────────┤
│ 平台层             IGamePlatform（SPI）                     │
│   native │ fabric │ neoforge │ forge │ aprism              │
├────────────────────────────────────────────────────────────┤
│ Minecraft 客户端进程                                        │
└────────────────────────────────────────────────────────────┘
```

**common** 源集包含平台层以上的全部内容，在各加载器分支间字节一致（按"每加载器一个分支"规范，每个加载器分支持有自己的副本）。

## 3. 控制通道

### 3.1 线程模型

- 传输线程只做 JSON 解析与校验。
- 校验通过的命令入有界 `LinkedBlockingQueue<ControlCommand>`（默认容量 1024；溢出回 `QUEUE_FULL` 错误）。
- 客户端 tick 事件每 tick 至多排空 `maxActionsPerTick`（默认 4）条命令，**在游戏线程**上执行，保证与游戏状态的线程安全。
- `Screenshot` 经平台帧末钩子在渲染线程执行；HTTP 响应阻塞直到抓取完成（默认超时 5 秒）。

### 3.2 传输

| 传输 | 端点 | 默认启用 |
|---|---|---|
| HTTP | `127.0.0.1:25585/despotes/v1/*` | 是 |
| CLI | 游戏进程 stdin，每行一条 JSON | 是 |
| FileDrop | 每 tick 消费 `despotes-in/*.json` | 否 |

HTTP 服务器：`com.sun.net.httpserver.HttpServer`，缓存线程池（最多 8 工作线程）。端点定义见文档 02。每个请求携带传输身份；调度器为每条执行的动作打上 `{source, transport, requestId}` 标签，用于可视化与日志。

### 3.3 安全闸门

- 绑定地址默认 `127.0.0.1`；无论绑定配置如何，HTTP 服务器**拒绝非回环来源**，除非该远程地址被列入 `security.allowSources`。
- `security.enabled=false`（紧急开关）禁用除 CLI 外的所有传输。
- 命令可由 `security.requireToken` + `security.token` 门控（默认关闭；回环来源可信）。

## 4. 输入注入

所有注入都作用于游戏内部处理器对象；绝不触碰操作系统输入设备。

| 动作 | 机制（各加载器通用） |
|---|---|
| 按键按下/释放 | 直接调用 Options 对象上 `KeyMapping` 的点击计数队列/按键状态表，并由 tick 调度器保持/释放。直接调用处理器，故无需窗口焦点。 |
| 打字（聊天/告示牌/书） | 直接向焦点编辑框组件的值追加文本（GUI 文本），或以 `/` 前缀经 `Connection` 发送聊天作为命令。 |
| 移动 | 每 tick 将合成状态应用到游戏线程上 `KeyboardHandler` 的移动字段（前/左/后/右/跳/潜行/疾跑）。 |
| 视角 | 在游戏线程直接写玩家旋转字段（增量或绝对值），可平滑。 |
| GUI 点击 | 在当前画面上解析 (x, y) 悬停的组件，然后以指定按键直接调用鼠标点击处理器。 |
| 世界交互 | 在游戏线程经 `gameMode`/`Connection` 构造客户端使用/放置包（攻击、使用物品、放置方块、丢弃）。 |

具体成员名由平台层按版本解析（映射：Fabric 1.20–1.21.x 为 intermediary/官方名，26.1+ 为官方名，Forge/NeoForge 为 MCPConfig 名）。

## 5. 画面截取

- 主路径：渲染线程上主帧缓冲绘制完成后，`glReadPixels` 读入预分配直接缓冲；编码 PNG（或 JPEG q=0.8）移至其他线程；存储或流式返回。
- 存储：游戏目录下 `despotes-shots/<时间戳>-<requestId>.png`（可配置），或由 `GET /despotes/v1/screenshot` 直接返回。
- 失焦截取：读取发生在 GL 上下文自己的线程上、swap 之前，因此无需窗口焦点。（部分驱动下最小化窗口可能产生黑帧——已记录的局限。）

## 6. 平台 SPI

```java
public interface IGamePlatform {
    String loaderId();                 // "native" | "fabric" | "neoforge" | "forge" | "aprism"
    void scheduleOnClientThread(Runnable r);
    void scheduleOnRenderThread(Runnable r);
    boolean isInGame();                // 已有客户端与世界
    PlayerHandle player();             // 不在世界中为 null
    ScreenHandle currentScreen();      // 无 GUI 为 null
    ShotHandle captureFrame(ScreenshotOptions o);
    void log(String line);
}
```

句柄（`PlayerHandle`、`ScreenHandle` 等）是 common 层接口，由各加载器以版本适配器类实现。这把所有 Minecraft 符号隔离在平台模块内，使调度器/动作层保持加载器无关。

加载器入口：

| 加载器 | 入口 | tick 钩子 |
|---|---|---|
| native | premain agent → Mixin 初始化 | Mixin 到客户端 tick 与帧末 |
| fabric | `fabric.mod.json` client entrypoint | Fabric API 客户端 tick/帧事件 |
| neoforge | `@Mod` | `ClientTickEvent.Pre/Post`、帧末事件 |
| forge | `@Mod` | 同名事件（旧总线变体） |
| aprism | `aprism.manifest.json` main entrypoint | Aprism CLIENT 阶段 + 客户端 tick 事件 |

## 7. 可视化

- **覆盖层**：左上角 HUD 列表显示最近 N 条（默认 8）外源操作：`[HTTP#42] key W hold 1.0s ✓`。经平台 GUI 绘制钩子渲染；F8 切换（可配置、可关闭）。
- **操作日志**：游戏目录下 `despotes-oplog.jsonl`，每条执行动作一行 JSON，含来源、传输、参数、结果、耗时。
- 两者默认开启，可在配置中关闭。

## 8. 构建与分支模型

按 Aprism 文档 §12 分支规范：**每加载器一个分支** —— `native`、`aprism`、`fabric`、`neoforge`、`forge` —— 外加 `main` 仅存放文档、规范与 CI 清单。

每个加载器分支的布局：

```
common/                  加载器无关控制核心（Gradle 工程）
<loader>/                加载器入口 + 平台 SPI 实现
<loader>-<mc>/           映射/API 分歧时按 MC 版本的子工程
gradle/libs.versions.toml（版本目录，Aprism §10.5）
```

| MC 范围 | Gradle | Java 目标 | 工具链 |
|---|---|---|---|
| 1.20 – 1.20.4 | 8.11 | 17 | Fabric Loom / ForgeGradle 等价物 |
| 1.20.5 – 1.21.4 | 8.11 | 21 | 同上 |
| 26.1 – 26.2 | 9.7 | 25 | Loom 1.18+ / NeoGradle 7.1+ |

## 9. 风险

| 风险 | 缓解 |
|---|---|
| MC 版本间成员名漂移 | 平台层版本适配器 + 经 MDL 对每个支持版本冒烟测试 |
| 第三方模组覆写处理器 | Despotes 直接调用处理器；冲突以测试失败暴露，按版本记录 |
| 不可信局域网来源触达控制端口 | 仅回环绑定 + 来源白名单 + 可选令牌 |
| 帧抓取阻塞渲染线程 | 有界抓取队列；readPixels 是唯一 GL 工作；编码移出该线程 |
